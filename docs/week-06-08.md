# Weeks 6–8 — The AI Agent (the centerpiece)

**Goal:** A LangGraph multi-agent system that consumes anomalies (from week 4–5), reasons over observability data via MCP tools, executes remediations through an OPA-gated tool layer with Slack approvals, and writes a postmortem.

## Architecture recap

```
NATS subjects:                          AI Agent (Python + LangGraph)
  anomalies.metric ──┐                  ┌─────────────────────────────┐
  anomalies.log    ──┼──► subscriber ──►│ Detector → Diagnostician →  │
  alerts.firing    ──┘                  │ Remediator → Verify → Report│
                                        └─────────────────────────────┘
                                              │           ▲
                                              ▼           │
                                        OPA decision    Slack HITL bot
                                              │
                                              ▼
                                        MCP tool servers
                                          ┌──────────────────────┐
                                          │ prom-mcp │ loki-mcp  │
                                          │ k8s-mcp  │ github-mcp│
                                          └──────────────────────┘
```

## Why multi-agent? (See ADR-001)

A single "do everything" prompt drifts: it forgets early-conversation findings, mixes diagnosis with action, and skips verification. A graph with explicit nodes:
- forces structured reasoning,
- gives each step its own narrow prompt + tool subset,
- gives us **per-node observability** (latency, token cost, success rate),
- lets us substitute or A/B test individual nodes.

## Day-by-day

### Week 6

**Day 1–2: MCP servers**

Three read-mostly servers, all in Python with the official MCP SDK:
- `prom-mcp`: tools = `query_instant`, `query_range`, `list_alerts`
- `loki-mcp`: tools = `query_logs`, `list_streams`
- `k8s-mcp`: tools = `get_pod`, `get_events`, `describe_deployment`, `restart_deployment*`, `scale_deployment*`, `rollback_argocd_app*`

`*` = write tools. Every write tool dispatches to OPA first.

**Day 3: OPA + tool gating**

Policy file `agent/policies/tools.rego`:
- `restart_deployment` allowed if: namespace ∈ {online-boutique}, last restart > 5min ago
- `scale_deployment` allowed if: target replicas ≤ 2× current, ≤ 20 absolute
- `rollback_argocd_app` allowed if: change initiated <30 min ago, requires HITL approval

**Day 4–5: Detector + Diagnostician**

`agent/graph/state.py` defines the typed `IncidentState`. `agent/graph/nodes/detector.py` classifies incoming events; `diagnostician.py` runs an investigation loop with the read tools until it produces a hypothesis with a confidence score.

### Week 7

**Day 1–2: Remediator + HITL**

`remediator.py` picks a remediation playbook based on the hypothesis. For low-risk actions (restart, small scale-up) it executes immediately. For high-risk (rollback, cordon, scale-down) it posts to Slack via the bot in `agent/slack_bot.py` and awaits approval.

**Day 3: Verifier**

After action, re-queries the same signals that triggered the incident. If still anomalous after N attempts, escalates (returns to Diagnostician with the failed-action note in state, max 3 loops to prevent infinite cycles).

**Day 4: Reporter**

Generates the postmortem markdown from the full `IncidentState` (events + tool calls + decisions). Posts a Slack summary thread; files a GitHub issue with the postmortem body.

**Day 5: Wire it up**

The whole thing runs as a Deployment subscribed to NATS. See `agent/main.py`.

### Week 8

**Day 1–2: Deterministic tests**

`agent/tests/` has fixture-replay tests: pre-recorded tool responses fed in, assertions on the graph's path and final action. This is what makes the system trustworthy — you can prove the graph behaves consistently.

**Day 3–4: Token / cost telemetry**

Each LLM call emits Prometheus metrics: `agent_llm_tokens_total{node, model, kind=input|output}`. Add a Grafana panel: dollars-per-incident. Cost-aware incident handling becomes visible.

**Day 5: Demo run**

Full Scenario A end-to-end. Record the video. This is your portfolio centerpiece.

## Verification checklist

- [ ] Agent processes 10 synthetic anomalies in a row without state leakage between them
- [ ] OPA denies a write to a non-allowed namespace (test in `agent/tests/test_opa_gating.py`)
- [ ] HITL approval round-trips through Slack and resumes the graph
- [ ] After a real chaos-injected restart, Verifier sees recovery and Reporter posts the postmortem
- [ ] Average cost per incident < $0.10 (record in your README — interviewers like numbers)
- [ ] Agent prompts versioned in `agent/prompts/` — no inline strings in Python
