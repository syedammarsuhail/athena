# Weeks 4–5 — Anomaly Detection (ML)

**Goal:** Two anomaly-detection models running on KServe, fed by Prometheus and Loki, emitting structured anomaly events that the AI agent will consume next week.

## Why ML, not just thresholds (and not just an LLM)?

- **Thresholds** can't catch slow drift, seasonal patterns, or correlated multi-signal anomalies.
- **LLMs** can't economically scan millions of metrics per minute. And they hallucinate.
- **Classical ML** is cheap, fast, deterministic, and explainable. Use it where it shines: pattern recognition at scale. Save the LLM for the reasoning step.

## Day-by-day

### Day 1 — Set up MLflow + KServe

```bash
git add platform/mlops/mlflow-app.yaml platform/mlops/kserve-app.yaml
git commit -m "feat(mlops): mlflow + kserve" && git push
```

### Day 2 — metric-isoforest: training

The training script (`ml/training/metric-isoforest/train.py`) pulls 7 days of metrics from Prometheus, fits an Isolation Forest per `(service, metric)` pair, and logs each model to MLflow.

Run it as a CronJob (`ml/training/metric-isoforest/cronjob.yaml`) — retrains nightly.

```bash
# Manual one-off run for first model:
cd ml/training/metric-isoforest
python train.py \
  --prom-url http://prometheus.monitoring.svc:9090 \
  --metrics container_memory_working_set_bytes,container_cpu_usage_seconds_total \
  --namespaces online-boutique \
  --window 7d \
  --mlflow-uri http://mlflow.mlops.svc:5000
```

### Day 3 — metric-isoforest: serving on KServe

Build the inference container (`Dockerfile`), push, deploy as an `InferenceService` (`serving/isoforest-inference.yaml`). The service exposes `/v1/models/isoforest:predict`.

Test:
```bash
curl -X POST -d @sample.json \
  http://isoforest.mlops.example.com/v1/models/isoforest:predict
# {"is_anomaly": true, "score": 0.78, "service": "cartservice", "metric": "memory"}
```

### Day 4 — Anomaly poller (closes the loop)

The poller (`ml/serving/poller/poll.py`) runs as a Deployment. Every 30s it queries Prometheus for the latest values, calls the KServe service, and publishes any anomalies to NATS.

### Day 5 — log-drain3: training & serving

Drain3 is a streaming log-template extractor. The service (`ml/training/log-drain3/serve.py`) consumes Loki via the websocket API, builds templates incrementally, embeds each new template with `sentence-transformers/all-MiniLM-L6-v2`, and runs HDBSCAN clustering. New rare templates → anomalies.

### Day 6 — Validate with a synthetic incident

Inject a memory leak into `cartservice`:
```bash
kubectl apply -f chaos/experiments/memory-leak.yaml
```

Within 60–90 seconds you should see:
1. Prom: memory line rising
2. isoforest poller: anomaly published to `anomalies.detected`
3. NATS subject has the event before the threshold alert fires

That's the **value-add over thresholds** — earlier detection.
